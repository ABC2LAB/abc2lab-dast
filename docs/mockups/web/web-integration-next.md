# 웹 연결 후속 작업

기준: **2026-10-23 / 정적 목업과 실제 제품 구현 구분**. 이 목록은 구현 순서이며 API나 서비스 제공자가 완성됐다는 뜻이 아니다. 현재 `app`은 조립 골격이고 Host·Report도 서비스 골격이다. 공유 계약의 세부 기준은 [S1 API 규격](../../planning/s1-api-spec.md), 배포 방향은 [로컬 배포 설계](../../planning/local-deployment.md)를 따른다.

## 현재 목업

작업 생성 → 작업 상세 → 그래프·취약점·재현 현황·검사 범위·보고서 이동을 합성 데이터로 검토한다. 대상·LLM·DB 호출은 없다. 생성 작업은 현재 탭에서만 유지하고 새로고침하면 초기화한다. 판정은 가상 작업 완료 시에만 발행하며 중단으로 결과·PoC를 만들지 않는다.

## 실제 연결 순서

| 순서 | 작업 | 완료 조건·선행조건 |
|---|---|---|
| 1 | 웹 입력·조회 경계 합의 | 대상/계정/모델 프로필 참조, 상태·오류·인가·취소 의미를 정한다. 목업의 임의 필드를 그대로 공유 계약으로 승격하지 않는다. Host·Report 공개 계약은 담당자와 먼저 확정한다. |
| 2 | `app` 웹 API와 서비스 주입 | 공개 포트로 시작·상태·중지를 연결한다. URL·모델 출력 자체가 실행 허가가 되지 않으며, API 요청과 worker 수명을 분리한다. 대상 전송 없는 제공자로 먼저 검증한다. |
| 3 | 작업 상세의 진행·상태 연결 | 같은 작업 ID로 상태를 받고 갱신 실패·중단·전송 불명을 보존한다. 화면 이동과 갱신이 추가 진단이나 자동 재전송을 만들지 않는지 확인한다. |
| 4 | 자산 인벤토리·Knowledge 그래프·Evidence 조회 | 인가된 발견/등록 엔드포인트, 부분 그래프와 비식별 근거 요약을 웹 표시용 데이터로 변환한다. 자산은 method·origin·경로 템플릿·변수 이름·출처를 보존하고 발견 여부와 전송·검사 상태를 분리한다. UI에서 AGE/DB를 직접 읽지 않는다. 스냅샷·원본 출처·관찰/추론/미확인 상태를 표시한다. |
| 5 | Judge·Report 결과·PoC 연결 | 저장·검증된 판정과 보고서만 표시한다. 보고서 작성·기록 재생·PoC 문서화는 새 대상 요청과 구분한다. 수정 확인은 원래 작업에 연결된 새 작업으로 생성한다. |
| 6 | 개발용 모델 설정 API | 새 진단에서 설정한 비밀 없는 프로필을 run 시작 시 고정한다. 자격 원문은 조회 응답·로그·브라우저 저장소에 남기지 않는다. 실제 연결 확인은 서버의 허용된 어댑터가 처리한다. |
| 7 | Compose·통합 검증 | `app`·`ollama`·`db` 구성, localhost 접속, 재시작·준비 상태·접근 권한을 검증한다. 실제 대상 전송은 별도의 D-0 확인과 내구 감사 준비 뒤에만 수행한다. |

UI 스택·조회 API 경로·진행 전달 방식과 서비스 저장소는 후속 구현에서 선택한다. 위 표를 근거로 다른 담당 모듈을 임의 수정하거나 실제 진단을 실행하지 않는다.
