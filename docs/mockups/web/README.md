# ABC2LAB 사용자 화면 목업

상태: **아홉 번째 시안 / 개요·작업 KG의 원형 시각화 통일 (2026-10-23)**. 화면 기준은 루트 [DESIGN.md](../../../DESIGN.md)를 따른다.

[ARTEX](https://github.com/jiwoochris/artex-global)의 밝은 사이드바·흰색 작업 영역·검정색 버튼·작업 표·탭 구성을 참고해 현재 목업에서 재구현했다. 원본 React 코드·로고·이미지는 포함하지 않는다. 참고 버전과 적용 범위는 [ARTEX UI 적용 기록](artex-ui-adaptation.md)에 정리한다.

외부 라이브러리 없는 HTML/CSS/JS 목업이다. 실제 서비스 API·대상 웹·LLM·DB를 호출하지 않는다. 모든 사례·전송 상태·연결 상태는 가상이며, 설정은 현재 탭의 메모리에만 둔다.

## 제공된 주요 화면 예시 반영

| 화면 | 현재 목업에 반영한 구성 |
| --- | --- |
| 대시보드 | 탐색 페이지·수집 API·발견 파라미터·진단 후보 지표, 웹 구조 미니 그래프, 최근 활동·작업·판정 |
| Knowledge Graph | 사용자/역할→페이지→엔드포인트→자원 구조, 노드 검색·확대/축소·범례·선택 상세, 기존 판정 근거 보기 전환 |
| 취약점 목록 | 후보·판정 발행·확인 취약점·오탐 검토 지표, ID·검사 유형·심각도·판정·설명/경로·기록일 표 |
| 취약점 상세 | 유형·설명·관련 엔드포인트·재현/검토 단계, 합성 요청·응답 형식, 기존 근거·PoC·타임라인 |

이미지의 숫자나 다른 취약점 유형을 진단 실적으로 복사하지 않는다. 수집 수는 명시한 합성 탐색 fixture에서 계산하며 차단·미실행 경로를 발견 페이지로 꾸미지 않는다. 파라미터는 엔드포인트별 경로 변수 이름 건수다. 별도 오탐 검토 기록은 없어 `—`로 표시하고 정책상 허용·판단불가를 오탐으로 집계하지 않는다. 실제 발견 시각이 없어 작업 날짜를 `기록일`로 표시한다.

## 열기

저장소 루트에서 다음을 실행하고 `http://127.0.0.1:8765`를 연다.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/mockups/web
```

`index.html`을 브라우저에서 직접 열어도 기본 이동은 가능하다. 복사·다운로드 검토에는 localhost 서버를 권한다.

## 둘러보기

- 개요에서 최근 완료/부분 완료 작업의 탐색 페이지·수집 API·파라미터·후보 수, 웹 구조 요약과 최근 활동을 확인한다. 진행 중 작업·확인 취약점·추가 검토 수는 별도로 표시한다. 지표는 표시된 작업 기준이며 전체 서비스의 안전 점수가 아니다. 개요에는 새 진단 버튼이 없으며 새 작업은 `진단 작업` 목록에서 시작한다.
- 상단 검색 버튼 또는 `Ctrl K` / `⌘ K`로 작업 ID·이름·대상을 찾는다. 방향키로 결과를 선택하고 Enter로 작업을 열거나 Esc로 닫는다. 진단 작업 목록에서는 검색과 상태 필터를 함께 사용할 수 있다.
- 개요와 `진단 작업` 목록에서 작업을 연다. 모든 작업은 `#scan/<작업 ID>` 상세로 들어간다. 생성 직후부터 완료·중단 뒤까지 같은 작업 상세 안에서 기록을 검토한다.
- 작업 상세 상단에 작업명·대상·상태·진행률을 유지하고 `요약 / 그래프 / 취약점·판정 / 재현 현황 / 검사 범위 / 보고서·설정`을 전환한다. 결과·그래프를 전역 메뉴로 분리하지 않으며 다른 작업은 작업 목록에서 선택한다.
- 새 진단에서 등록 대상·보호 규칙을 확인한다. URL 규칙 미리보기에 `/api/orders/example`, `/login`, `/api/payments/example`, 외부 URL을 입력해 차이를 살펴본다. 실제 주소에는 접속하지 않는다.
- 계정 프로필을 선택한 뒤 `모델·실행 설정`에서 Ollama 또는 외부/내부 API를 선택하고 모델·timeout·토큰 상한·실행 한도를 설정한다. 별도 설정 메뉴와 `AI 사용 안 함` 선택지는 없다. 연결 확인은 합성 상태만 재생한다.
- 마지막 단계에서 사전 점검을 실행한다. `평가 계정 인증 만료` 예시는 시작을 막는다. `정상 준비`로 바꾸고 다시 점검한 뒤 범위를 확인해 시작한다. 이전 단계에서 대상·계정·모델·실행 한도를 바꾸면 다시 점검한다.
- 생성 직후 작업 상세에서 가상 진행률을 확인하고 그래프·재현 현황을 열거나 중지한다. 탭 이동 중에도 같은 가상 작업이 유지된다. 완료 시 현재 탭에 머물며 결과를 검토한다.
- 자동 갱신 중에도 선택한 노드·관계·탭의 키보드 초점을 유지한다. 단계가 바뀔 때만 상태 안내를 갱신한다. 이 목업은 완료 시 판정하므로 중단된 작업에는 판정·PoC를 새로 만들지 않는다. 관찰 기록과 미실행·미확인 사유는 보존한다.
- `재현 현황`은 후보의 기준·교차 비교와 정책 근거 처리 상태, 차단·미실행·전송 불명 사유를 보여준다. 최종 판정 전에는 후보를 확정 취약점으로 표시하지 않는다. `재현 근거 확보`는 저장된 비교 근거이며, 문서화된 PoC를 별도 자동 재실행 중이라고 표시하지 않는다.
- 결과와 검사 범위를 오가며 경로별 기준 관찰·교차 관찰·정책 근거를 확인한다. 행 선택·검색·추가 확인/차단/전송 불명 필터로 미완료 사유를 확인한다.
- 선택 작업 수, 등록된 동작 수, 요청 수를 구분한다. 검사 범위의 완료는 취약점 없음이나 웹 전체 검사 완료를 뜻하지 않는다.
- 상세의 검사 유형·기록일·재현/검토 단계와 요청·응답 형식을 함께 확인한다. 요청은 실행하지 않는 placeholder이며 응답은 합성 예시다. 전송 불명·정책상 허용·신원 미확인·미재현 사례에는 성공 응답을 만들지 않는다. 기존 판정 근거·PoC·타임라인과 근거 연결 흐름도 유지한다.
- 확인된 취약점에서 `수정 확인 진단`을 시작한다. 새 run에서 `같은 문제 다시 확인`, `기존 경로에서 미재현`, `신원 근거 확인 불가` 중 시연할 예시를 고른다. 과거 진단과 연결 이력은 현재 탭에 보존하며, 미재현을 수정 완료로 표시하지 않는다.
- HTML 예시 보고서를 내려받거나 placeholder PoC를 복사한다. PoC를 실행하는 기능은 없다.
- 작업 상세의 `그래프`에서 세 관점을 전환한다. 자산 그래프는 도메인→웹 서비스→경로 그룹→엔드포인트 계층과 검사 상태, KG는 웹 구조와 정책·판정 근거, 진단 흐름은 스캐너의 작업·전송·판정 순서를 표시한다. 자산의 URL 구조와 관찰로 입증된 관계를 구분하며, 근거 없는 페이지·자원 연결을 만들지 않는다.
- KG의 `웹 구조`는 개요와 같은 유형별 색상의 원형 노드·곡선으로 사용자·역할→페이지→엔드포인트→자원을 보여준다. 원 옆에서 유형·이름·관계 상태를 읽고 선택 상세에서 전체 경로를 확인한다. 페이지 연결은 명시한 합성 탐색 자료이며 역할 프로필과 신원 검증을 구분한다. 기본 4개 경로를 먼저 표시하고 `전체 경로 표시`로 나머지를 펼친다. 검색은 숨긴 경로도 찾는다. 노드·관계를 선택하면 해당 사례의 판정으로 이동할 수 있으며 공유 계정 노드에 임의 사례를 연결하지 않는다.
- KG의 `판정 근거`는 기존 핵심 7개 노드를 보여주고 `세부 관계 표시`로 역할·미검증 가설을 펼친다. 사례 선택과 상세의 `KG에서 보기`는 이 관점에서 해당 사례를 연다.
- 그래프는 100% 배율의 큰 노드·유형 아이콘·상태 문구와 읽는 순서를 표시한다. 자산은 그룹별 4개 엔드포인트를 기본으로 대표·전송 불명·차단·미실행 항목을 먼저 표시한다. 나머지는 `엔드포인트 N개 더` 노드에서 목록을 보고 4개씩 펼치거나 항목을 바로 선택한다. 그룹 상세의 접기, `전체 펼치기`, `기본 보기`도 사용할 수 있다.
- 자산 검색과 `검사 상태` 필터는 접힌 항목도 검색하고 상위 도메인·서비스·경로를 유지한다. 엔드포인트를 선택하면 메서드·origin·경로 변수 이름·합성 출처·전송 해석·관련 판정이 아래에 표시된다. 실제 값·원문 응답·토큰은 표시하지 않는다. 작업 전체 수, 검색 결과 수, 펼친 수를 구분한다.
- 노드·선을 선택하면 해당 연결이 강조되고 전체 이름·출처·주변 연결을 캔버스 아래에서 확인한다. 반복 관계 라벨은 선택하거나 `관계 이름 표시`를 켰을 때 보인다. `맞춤`은 전체 구조 보기, `100%`는 읽기 크기 복원이다. 모바일은 기본 글자 크기를 유지하고 그래프 내부를 스크롤한다.
- 그래프의 사례 선택, 노드·관계 선택, 검색·관계 상태 필터, 주변 연결, 기능 펼치기, 확대·배경 드래그를 검토한다. 상세에서 같은 작업의 판정 근거로 이동할 수 있다. 별도의 진단 선택기는 두지 않는다.
- 검색·필터 뒤 표시 경로 수와 작업 전체 수를 구분해 확인한다. `RUN-002`는 일부 확인 불가 상태와 미완료 범위 경고, 생성 후 중지한 작업은 판정 미발행과 관찰 기록 보존을 확인하는 예시다.
- 진단 흐름의 재생·일시정지·이전/다음·슬라이더로 저장된 합성 기록을 탐색한다. 정상·차단·전송 불명 흐름을 구분하며 재생은 새 진단을 만들거나 대상 요청을 보내지 않는다.

모바일 메뉴·필터 결과 없음·점검 실패·진행 중·중단·완료·판단불가 화면도 검토한다. 좁은 화면에서는 검사 범위 표를 좌우로 이동할 수 있다. 새로고침하면 데모 초기 상태로 돌아간다. API 키 등 실제 비밀값을 입력할 필요가 없다.

## 범위

실제 프런트엔드 기술 선택이나 계약·서비스 구현 완료를 의미하지 않는다. 사용자 피드백을 반영한 뒤 실제 API 연결 범위를 별도로 확정한다. 서비스 코드·루트 설정·잠금 파일은 변경하지 않는다.

실제 제품 연결 작업의 순서는 [웹 연결 후속 작업](web-integration-next.md)을 따른다. 이 목록은 구현 전 작업이며 목업 검증과 구분한다.

이번 UI 변경은 Chromium에서 검색·상태 필터·키보드 이동과 320/390/1024/1440px 화면을 검토했다. 기존 작업 생성·중단·수정 확인·보고서·그래프 흐름도 함께 검사했으며, 외부 요청은 발생하지 않았다. 이 확인은 정적 목업 범위이며 실제 서비스 통합·다른 브라우저·접근성 적합성 인증은 포함하지 않는다.

`task-detail.js`는 작업 ID 조회·공통 헤더·요약·재현 현황·설정 기록, `scan-settings.js`는 새 진단의 모델·실행 설정, `scan-workflow.js`는 범위·사전 점검·검사 범위·수정 확인, `asset-graph.js`는 엔드포인트 자산 계층·묶음·선택 상세, `web-surface.js`는 명시적 탐색 fixture·수집 지표·미니 그래프·웹 구조 KG, `finding-examples.js`는 검사 유형·기록일·검토 단계·합성 요청/응답 형식, `graphs.js`는 공통 그래프 표시와 KG·흐름 재생을 담당한다. 자산 목록은 현재 작업의 합성 검사 경로에서 만든 목업이며 실제 발견 인벤토리 API가 아니다. 공개 API·공유 계약·AGE 조회 제공자는 구현하지 않는다. 그래프의 관계 상태와 취약점 판정은 별개이며 원문·인증 값·평가 정답을 표시하지 않는다. 화면의 상태·예시 한도는 새로운 공유 계약이 아니다. 실행 중 이상 감시는 고도화 단계의 별도 과제로 남긴다.
