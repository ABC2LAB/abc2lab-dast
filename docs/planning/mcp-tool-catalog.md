# ABC2LAB — 상용 배포용 기본 MCP 도구 목록

- 기준일: 2026-10-19
- 최종 수정일: 2026-10-20
- 적용 문서: [MCP 아키텍처](mcp-architecture.md)
- 설계 기준: 이 문서와 MCP 아키텍처 두 파일을 현재 설계 문서로 유지한다. 지문 기억은 아키텍처 §6.3에 통합한다.
- 선정 기준: 비공개 온프레미스 제품에 동봉·배포하는 보수적 기준. 상용 사용과 제품 통합·재배포 조건을 구분한다.
- 결정 수준: 기본 엔진·역할·허용 모드를 설계에 명시한다. 설치·의존성 추가·구현·최종 패키지의 라이선스 적합성 검증 완료를 뜻하지 않는다.
- 적용 단계: 전체 10도구는 목표 제품의 기본안이다. 작은 읽기 IDOR 슬라이스는 연결 검증용이며 최종 품질 범위를 제한하지 않는다. 융합 Discovery·SPA/인증·일반/흐름 검사는 유형별 품질 기준으로, 영속 기억은 관찰 정확성·범위/재확인·효용 기준으로 검증한다. 개발 일정 때문에 지원 품질을 축소하는 단계가 아니다.

## 1. 기본 구성

**목표 제품의 외부 진단 엔진은 Playwright, HTTPX, OWASP ZAP, Nuclei 네 개다. 최초에는 Playwright·HTTPX와 자체 읽기 인가 비교부터 연결한다.** KG 조회·위협 가설·인가/업무 흐름 비교는 자체 도구로 구현한다. 외부 엔진마다 MCP 서버를 늘리지 않고 목표 Knowledge/Web Diagnostic 서버의 어댑터로 연결한다.

기본 도구의 실행은 Host 프로그램이 관찰·등록 탐색 전략·검사 패턴으로 계획한다. LLM의 판단·도구 선택·payload 생성이 있어야만 실행되는 구조로 만들지 않는다. 모델은 KG 기반 추가 의미·위협 가설을 제안하며 기본 경로와 동일한 정책·Gateway를 거친다.

AI 사용 모드의 핵심 평가 대상은 관계·인가 가설 생성·반증 처리·근거 충분성 판단이다. 기본 진단의 완주와 이 하위작업의 품질을 구분한다. 모델 비교는 동일 관찰 입력의 추론 평가와 추가 탐색을 포함한 E2E로 나누며 도구/서버 수를 늘려 해결하는 결정이 아니다.

KG는 프로그램 기본선과 AI 보강의 공통 제품 구성으로 채택하고, 저장소는 **PostgreSQL + Apache AGE**로 구성하는 방향을 정한다. PostgreSQL의 서비스별 관계형/JSONB 정본에 민감값 제거한 탐색·정책·가설·검증·근거 참조를 축적하고, Knowledge의 검증된 Projector가 AGE에 관계/업무 경로와 근거를 투영한다. 각 서비스는 자기 정본만 기록하고 Knowledge 저장소 어댑터가 자기 관찰/후보·기억 정본과 AGE 쓰기/등록 질의를 관리한다. LLM/실행 도구에 DB 자격·raw SQL/Cypher를 노출하지 않으며 같은 물리 DB의 자동 동기화/격리를 가정하지 않는다. 원본/그래프 revision·반영 지연/누락·중복 재처리·재구축을 검증하고 허용된 큰 근거 자료·세션/비밀의 보호 저장 경계는 유지한다.

메모리 최소화보다 근거 보존·충분한 문맥·관계 조회/정합성을 우선하되 PostgreSQL/AGE·투영/조회·브라우저/모델의 전체 자원과 한도 실패를 측정·통제한다. 인메모리 대역은 독립 테스트용이며 목표 통합 검증은 실제 PostgreSQL+AGE에서 수행한다. 모델 비교는 같은 정본/KG snapshot 또는 초기 상태와 PostgreSQL/AGE 버전·등록 질의/투영 프로필을 고정하며 H1 자원 상한을 사후 완화하지 않는다. 구성·저장/투영 계약은 [아키텍처 §6.2](mcp-architecture.md#62-kg-확정-구성과-구현-경계), Docker·영속 볼륨·장애/복구는 [§10](mcp-architecture.md)을 따른다. 저장소는 진단 엔진 네 개와 별도 구성요소이며 새 MCP 서버/도구를 추가하지 않는다.

외부 기준 LLM에서 내부·로컬 모델과 크기/양자화 후보로 바꾸는 연결은 **AI Reasoner 내부 Model Adapter**가 맡으며 새 MCP 서버/도구를 추가하지 않는다. 공통 추론 입출력·오류/사용량·능력/모델 프로필과 교체 검증은 [아키텍처 §6.4](mcp-architecture.md#64-model-adapter와-외부로컬-모델-교체-계약)를 따른다. run의 모델·프롬프트·어댑터·호출 모드를 고정하고 모델 교체는 새 run/별도 평가군으로 수행하며 비교 중 다른 모델로 자동 fallback하지 않는다. 외부 연결은 환경이 자료 전송을 허용한 모델 서비스와 민감값 제거 요약에 한정하고, 온프레미스 기본 동작에는 외부 모델을 요구하지 않는다. 고정 입력 A4와 별도 E2E 비교·모델별 품질/자원 판정은 [§11.1](mcp-architecture.md)을 따르며 모델 교체로 도구 노출·정책·Judge 권한을 늘리지 않는다.

| 기본 구성 | 역할 | MCP 도구 예시 | 확인한 상위 라이선스 | 기본 허용 모드 |
|---|---|---|---|---|
| Playwright SDK | 브라우저 탐색·DOM/동작·네트워크 관찰, 등록 인증 처리 | `web_observe` | Apache-2.0 | 격리 브라우저·승인 동작·대상 통신 통제 |
| HTTPX 라이브러리 | 요청 재현·응답 비교·범위/timeout 제어 | `http_observe` | BSD-3-Clause | Python HTTP 어댑터 내부에서 승인 요청만 실행 |
| OWASP ZAP | 관찰한 트래픽의 패시브 보안 분석 | `passive_analyze` | Apache-2.0 · 코어 기준 | 수집된 메시지 분석만. Active Scan·공격 모드·스파이더 자동 실행 제외 |
| Nuclei 엔진 + 선정 템플릿 | 반복 가능한 일반 취약점/설정 검사 | `template_check`, 허용 프로필의 `sql_injection_check` | MIT · 엔진/공식 템플릿 각각 확인 | 검토·고정한 HTTP 템플릿만 |

HTTPX는 Python HTTP 클라이언트 라이브러리이며 ProjectDiscovery의 동명 `httpx` CLI와 다르다. 여기서는 후자를 별도 기본 도구로 추가하지 않는다. 자체 구현 항목은 제품 전체의 저작권·라이선스를 대신 결정하지 않는다.

## 2. 기본 노출 도구와 책임

Knowledge MCP의 기본 도구는 3개, Web Diagnostic MCP의 기본 도구는 7개다. 아래 목록은 공개 계약 설계용 이름이며 실제 Schema·구현 완료를 의미하지 않는다.

이 목록은 전체 등록 목록이며 모델에게 매번 전부 전달하는 목록이 아니다. 초기 모델 노출은 작업에 필요한 Knowledge 조회·근거 확인·가설 제출을 중심으로 하고 Web 실행 도구는 Baseline Planner/Scheduler가 프로그램으로 호출한다. 관계 분석·추가 계획·설명 보조별 노출 범위는 [아키텍처 5절](mcp-architecture.md)을 따른다. 프로그램의 도구 호출에는 모델의 선택/응답을 요구하지 않는다.

10개 도구는 프로그램에서도 호출할 수 있다. 등록 패턴의 가설과 모델 제안은 신뢰된 호출 출처로 구분하고 `hypothesis_submit`의 형식 검증을 취약점 확정으로 해석하지 않는다. 모델 없이 관찰 KG·기본 후보·허용 검사·근거 판정·기본 보고를 연결하며, 필요한 관찰/정책 근거가 없으면 해당 범위를 미실행/판단불가로 기록한다.

|---|---|---|---|---|

엔진이 기본 구성에 있다는 이유로 모든 기능을 활성화하지 않는다. 검토한 실행 프로필이 없거나 통신·부작용을 통제할 수 없으면 해당 검사는 비활성/차단하고 진단 한계에 표시한다. SQLi·XSS 등 지원 범위는 실제 승인된 검사 ID와 재현 근거별로 명시하며 엔진 이름만으로 전체 지원을 주장하지 않는다.

유형별 지원표에는 필요한 관찰·기대 인가/업무 정책 근거·프로필/판정 코드 버전·비파괴 확정 가능 조건·의심/미검증 조건을 공개한다. 읽기 전용 인가 확정의 본근거는 (별도 근거로 확인한 기대 접근 정책) + (유효한 계정 맥락) + (동일 객체의 소유자 기준·교차 접근 비자명 실데이터 일치)이며, 목록 차이·id-echo는 보조 근거다. 실데이터 비교는 실행 영역 내 정규화 후 HMAC로 수행하고 해시·일치 결과만 저장한다(확정 오라클이 아니라 비교·증거 보호 수단). 쓰기 필수 업무 흐름은 실행 차단하며 승인+DB 초기화 reproduction 모드를 추가하지 않는다. 확정하지 못하는 범위는 안전정책상 검증 불가(제품 경계) / 오라클 미구현(구현 backlog) / 탐색·관찰·추론 실패를 구분하며, 확정 조건을 완전히 못 채우면 의심·판단불가로 보수적 판정한다. 상세 판정 경계·확정 조건·통제 데모는 [아키텍처 §11.4](mcp-architecture.md)를 따른다.

최초 읽기 수평 인가의 정책 근거는 운영자가 신뢰된 관리 창구에 등록한 명시적 기대 정책·적용 범위/예외·출처/버전으로 정한다. 정책 부재·만료·충돌/예외 미해소는 확정 유보이며 탐색은 계속한다. 이 정책 입력은 오프라인 평가 정답과 분리한다. 소유자 ID만으로 객체 고유성을 인정하지 않고 실제 객체별 데이터를 별도로 확인한다. 공격자 자기 객체는 보조 대조이며 필수 전제로 두지 않는다.

이 오라클의 `CONFIRMED`는 유효한 등록 정책과 실행 근거에 따른 위반 판정이다. 운영자는 정책의 정확성·적용 범위/예외를 확인하고, 제품은 정책 출처·버전·유효성·충돌 및 실제 계정/객체/접근 근거를 검증한다. 반복 조회에서 변하는 필드는 정규화 제외 후보로만 다루고 객체 구분·권한·비자명 실데이터 근거를 보존하며, 알려진 쌍과 확보 가능한 대상 대조로 검증한다. 같은 소유자의 복수 기존 객체·단일 객체·공격자 자기 객체 없음은 평가 사례로 포함하되 모든 운영 대상에 객체 2개를 요구하지 않는다. 정규화 절차·정책 책임과 보고는 [아키텍처 §11.4](mcp-architecture.md), fixture 구성은 [§11.3](mcp-architecture.md)을 따른다.

기존 도구의 API·SDK·CLI를 자체 어댑터 내부에서 호출한다. 범용 셸·옵션 문자열·임의 코드·임의 템플릿 URL을 LLM 입력으로 받지 않는다. 공식 또는 커뮤니티 MCP 서버도 엔진과 별도의 배포물로 평가하며 무검토 등록하지 않는다.

핵심 도메인 함수와 입출력 계약을 먼저 검증하고 MCP는 인증/참조 인가·입력/결과 매핑·감사/취소를 전달하는 얇은 어댑터로 붙인다. 직접 호출과 MCP 호출의 진단/판정 로직을 따로 만들지 않는다. MCP 이전의 직접 함수도 동일 정책/Gateway를 거치며 2서버·10도구의 동시 구현을 첫 완료 조건으로 두지 않는다.

기본 검사 입력은 버전이 있는 패턴/프로필과 관찰 참조에서 프로그램이 구성한다. SQLi 등 payload도 검토된 검사 프로필의 범위에서 생성한다. 모델이 제안한 미등록 공격 방법이나 임의 payload는 자동 실행 도구에 전달하지 않는다. 모델이 실패하면 기본 도구 실행을 계속하고 보강 제한을 보고한다.

관찰 채널은 [아키텍처 4.1절](mcp-architecture.md)의 공통 후보 목록에 출처·계정/상태·필요 관찰을 연결한다. 작업 배정/대여/예산의 정본은 Scheduler다. JS/OpenAPI의 경로 선언·패시브 단서는 관찰 후보이며 현재 동작/접근 허용이나 검사 완료로 세지 않는다. 원격 명세/자산 요청도 통제하고 Service Worker 관찰 모드·포착 한계와 설정 변경의 앱 동작 차이를 기록한다.

AI에는 페이지/동작 의미·계정/세대·자원 관계 경로·기대 정책/예외·기준/비교·지지/반증·미확인 조건을 작업별 문맥으로 충분히 제공한다. Context Builder는 필수 항목·참조·출처·전달 상태를 점검하고 기존 지식 도구의 단계 조회·관계를 보존하는 분할로 보완한다. 초기 문맥과 추가 조회 모두 같은 민감값 제거·범위/예산을 적용하며 필수 정보의 조용한 잘림이나 정보 부족의 정상 판정을 허용하지 않는다. 충분성은 실행 허용/취약점 확정이 아니며 원문·인증 비밀·개인정보·평가 정답은 모델에 전달하지 않는다. 문맥 구성/요약 버전·실제 전달/누락·비교군의 동일 정보와 한도 실패 집계는 [아키텍처 §4.2](mcp-architecture.md#42-context-builder와-추론-정보-충분성)와 [§11.1](mcp-architecture.md)을 따른다. 추가 MCP 서버/도구를 만들지 않는다.

사용자 화면의 그래프 시각화도 Knowledge/Evidence 공개 조회 기능을 재사용한다. 사용자 UI/API가 인증·자료 권한과 대상/run·snapshot/revision을 확인해 등록된 부분 그래프/근거 조회를 호출하고, 브라우저에는 민감값 제거 노드/관계·근거/정책/판정 참조·반증·누락/지연·후속 조회 참조를 전달한다. 사용자 화면과 모델 조회는 허용 프로필을 구분하되 같은 범위/민감값 보호를 적용한다. 관찰/추론/검증·취약점 판정·allow/block·전송 unknown을 따로 표시하고 스캐너 이력을 대상 업무 흐름으로 오인하지 않게 한다. 상세 UI/API·읽기 전용·권한/커서/캐시·한도/성능 계약은 [아키텍처 §6.5](mcp-architecture.md#65-사용자-화면의-그래프-시각화)를 따른다.

그래프 클릭·필터·주변 펼치기는 저장 자료 조회이며 대상 요청·새 검사·모델 호출을 자동 발생시키지 않는다. 전체 그래프를 한 번에 반환하지 않고 깊이·노드/관계·응답 크기·시간/동시성 상한과 생략/unknown 표시를 유지한다. 화면의 표시/배치 변경은 원본 KG/판정을 수정하지 않으며 브라우저에 DB 자격·raw SQL/Cypher·범용 MCP 실행 권한을 주지 않는다. 시각화용 MCP 서버/도구를 추가하지 않고 기존 2서버·10도구를 유지한다. 실제 화면 구현과 R18/A27 검증은 공개 조회 계약을 확보한 후 수행한다.

영속 기억 도입 시 관찰 어댑터가 기술·페이지·엔드포인트 특징을 추출하고 Knowledge가 범위/최신성·현재 재확인과 함께 기억한다. 현재 관찰 정규화·기본 중복 제거와 구분하고 기억 비사용/사용의 탐지·누락/오탐·시간/자원을 비교한다. 기존 조회 도구로 허용 요약을 제공하며 추가 MCP 서버/도구를 만들지 않는다. 과거 판정·실행 허용 복사나 계정/자원 비교 생략은 금지한다. 상세 규칙은 [Fingerprint 기억 설계](mcp-architecture.md#63-fingerprint-memory)를 따른다.

## 3. 기본 프로필의 실행 제한

- **Playwright:** 화면·입력 지점·트래픽 관찰을 결합한다. LLM에 범용 JavaScript·파일·셸 실행을 주지 않는다. UI 클릭·폼 전송도 실제 요청 정책을 따르며 정상 로그인·세션 갱신 외 업무 쓰기는 차단한다.
- **HTTPX:** 요청/자원 참조에서 서버가 실제 목적지·헤더·인증을 구성한다. Cookie·토큰 값은 모델에 노출하지 않는다. 리다이렉트·재시도·DNS/TLS·계정 맥락과 요청 예산을 재검사한다.
- **ZAP:** 관찰된 트래픽을 패시브 분석하는 기본 구성이다. 분석 도구에 스파이더·Active Scan·공격 모드를 노출하지 않는다. 원문 메시지는 격리 작업 영역에서만 처리하고, 인증 값·개인정보가 포함된 히스토리·세션 DB·원문 로그를 공유/영속 근거로 내보내지 않는다. 애드온은 필요한 항목만 선별한다.
- **Nuclei:** 템플릿 ID·내용 해시·엔진/프로필 버전을 고정한 HTTP 검사만 사용한다. 임의 템플릿·code·headless·javascript·file·network 실행, OAST/Interactsh·브루트포스·인증 공격·상태 변경을 기본 범위에서 제외한다. 정상 인증은 기존 실행 창구만 맡는다.
- **공통:** Broker가 신뢰된 작업에 묶인 도구 목록·정의 버전·결과/호출 한도를 관리하고 미노출 도구 호출을 거절한다. 서버도 작업의 허용 도구·프로필·범위를 검사한다. 모델에는 필요한 구조화 요약·근거 참조·상태·반증·최신성/잘림 한계만 제공한다. 고수준 작업 내부는 코드/SDK로 처리하며 각 내부/파생 요청에 Gateway·예산·취소 검사를 적용한다. HTTPS 내부 요청을 확인할 수 없는 통합 방식은 허용 프로필로 등록하지 않는다.
- **대상 허가:** 조직이 소유/진단 허가를 확인해 등록한 자산 범위만 검사한다. 신뢰된 허가 참조·버전·유효기간을 run과 요청에 연결하고 미등록/만료/취소/범위 밖 대상은 전송 전에 차단한다. 계정 보유나 발견 링크를 허가 증명으로 취급하지 않는다.
- **감사 연결:** 가설 또는 기본 탐색 목표·작업·정책/사유·실제 요청 시도·근거/판정을 연결한다. 정책 allow와 실제 전송은 구분하고, 차단·미실행·전송 여부 불명도 보존한다. 생산자별 신뢰 기록에서 run별 감사 타임라인을 만들며 새 MCP 도구를 추가하지 않는다. 상세 내구 기록·중지·민감값 제거는 [아키텍처 8절](mcp-architecture.md)을 따른다.
- **재제출/전송 불명:** 같은 작업 ID 재제출은 기존 상태/결과 조회로 처리한다. 전송 여부가 unknown인 시도를 자동 재전송하지 않으며, 별도 후속 확인도 현재 정책·인증·예산과 원 시도의 감사 연결을 유지한다.
- **인증 세션:** Web Execution 내부에서 계정별 격리·실제 주체·세대·대여/종료·제한된 복구·갱신 직렬화를 관리한다. 쿠키 공유를 범용 SPA/Bearer 지원으로 해석하지 않는다. 비교 전후 기준 관찰·계정/세대를 연결하고 복구 실패를 Guest 비교나 접근 거절/성공으로 바꾸지 않는다. 초기 단일 폼/쿠키와 등록 정상 갱신 프로필, 미지원 인증은 [아키텍처 8.3절](mcp-architecture.md)을 따른다.

ZAP의 패시브 분석은 자체적인 요청 변조/공격 검사와 구분된다. Nuclei의 템플릿 라이선스·서명·안전 태그는 실행 영향의 무해성 보장이 아니므로 별도의 요청·상태 변화 시험이 필요하다. 관련 공식 기능 근거는 [ZAP 패시브 스캔](https://www.zaproxy.org/docs/desktop/start/features/pscan/), [ZAP API](https://www.zaproxy.org/docs/api/), [Nuclei 문서](https://docs.projectdiscovery.io/tools/nuclei/overview)다.

Playwright의 Apache-2.0은 동봉 브라우저 바이너리 전체의 라이선스를 대신하지 않는다. ZAP 코어의 Apache-2.0도 모든 애드온·JRE·이미지 조건을 대신하지 않는다. Nuclei 엔진과 템플릿은 서로 다른 배포물로 추적한다. 상위 라이선스가 허용적이라는 사실과 최종 제품의 모든 배포 조건 충족 여부를 구분한다.

**PostgreSQL+AGE 배포·라이선스:** 저장소 제품의 방향은 PostgreSQL + Apache AGE로 정하고 실제 호환 버전·이미지·드라이버는 배포 검증 후 고정한다. 2026-10-20 확인 기준 PostgreSQL 코어는 PostgreSQL License, AGE 코어는 Apache-2.0이다. 이 코어 라이선스는 비공개 상용 제품 결합·재배포를 허용하지만 실제 배포물의 라이선스/저작권·해당 NOTICE·수정 고지와 개별 의존성 조건을 준수해야 한다. [PostgreSQL 라이선스](https://www.postgresql.org/about/licence/), [AGE LICENSE](https://github.com/apache/age/blob/master/LICENSE), [AGE 개요](https://age.apache.org/overview/)

| 결정 항목 | 기본 배포물에 포함하기 전에 확정할 내용 |
|---|---|
| 호환 버전·접속 | PostgreSQL major/AGE 버전·드라이버·이미지 digest를 함께 고정. 필요한 openCypher/경로·트랜잭션·접속 초기화/연결 풀·schema/인덱스 검증 |
| 고객 공급 방식 | 고객 자체 취득과 제품의 이미지/바이너리·오프라인 묶음 제공을 구분하고 각 형태의 고지/동봉물 관리. DB 서비스와 영속 볼륨·보호 설정을 구분 |
| 코어 재배포 | PostgreSQL의 저작권/라이선스 고지, AGE의 LICENSE·해당 NOTICE·수정 표시와 별도 포함물 조건 확인 |
| 별도 구성물 | SQL/AGE 드라이버·추가 확장·베이스 이미지·시스템/전이 의존성의 LICENSE/NOTICE·SBOM. 코어 라이선스를 모든 동봉물에 그대로 적용하지 않음 |
| 배포 완료 기록 | 정본/그래프/외부 근거 참조의 백업 복구·업그레이드, 권한·자원/동시성/쿼리 상한과 의무 이행물을 배포 구성에 연결. 미검증 버전/이미지/확장을 기본 배포물에 추가하지 않음 |

PostgreSQL과 AGE는 하나의 호환 구성으로 시험하고 Docker 이미지에서도 버전을 함께 고정한다. 공식 배포 표의 지원 범위를 확인하며, 오래된 설치 예시의 버전 목록만으로 최신 호환성을 판정하지 않는다. 상위 지원 표가 실제 제품의 질의 호환성·백업/복구·장애 안전 검증을 대신하지 않는다. [AGE 공식 다운로드/호환 버전](https://age.apache.org/download/)

경로 질의의 선행 근거로 AGE 1.6.0/PostgreSQL 16 소스 빌드 환경의 PoC 통과 보고(사용자 전달, 2026-10-20)를 기록한다. 0홉 포함/범위 제한 도달성·추적 경로/홉 수와 재귀 CTE 대조 결과·확인 범위는 [아키텍처 §6.2](mcp-architecture.md#62-kg-확정-구성과-구현-경계)를 따른다. 이번 세션에서 원본 실행 자료를 확인하거나 재현하지 않았으며, 보고된 버전은 제품 배포물의 최종 고정이나 규모/성능·백업/장애 안전 검증 완료를 뜻하지 않는다. 수직 슬라이스의 영속 통합 초기에 실제 배포 조합을 검증하고, CTE 비교 결과를 운영 자동 fallback으로 확대하지 않는다.

MIT·BSD·Apache 등 실제 적용 라이선스의 고지·재배포 조건을 제품 빌드에 반영한다. 런타임의 자동 엔진/애드온/템플릿 업데이트·클라우드 업로드·불필요한 외부 통신은 기본 비활성화하고 검증한 오프라인 업데이트 묶음으로 관리한다. 외부 연결이 필요한 진단 대상 통신과 공급자 서비스 연결 권한은 구분한다.

이 문서는 진단 엔진·모드와 PostgreSQL+AGE 저장소 방향의 선정 기록이다. 실제 릴리스 버전·브라우저·애드온·템플릿·전이 의존성의 해시를 확정한 배포 구성 명세와 SBOM은 구현·패키징 단계에서 만든다. PostgreSQL/AGE 호환 버전·드라이버·이미지는 위 검토와 아키텍처 §6.2·§10 검증을 통과한 뒤 고정한다. 이 문서는 설치/제품 통합·재배포 적합성 확인 완료를 뜻하지 않는다. MCP SDK·모델 가중치 등 도구 목록 밖의 구성요소도 별도 선정 대상이다.

## 6. 도구 등록 전 확인할 기준

1. 공식 출처·버전/해시·라이선스·동봉물·고지 정보가 없으면 기본 빌드의 등록 대상에서 제외한다.
2. 입력 위조·다른 run/계정·원문 비밀·임의 옵션·비등록 템플릿·외부 지시로 권한이 확대되지 않는지 확인한다.
3. 대상/파생 요청·프로토콜·포트·콜백·재시도·취소·예산이 실제 경계를 우회하지 않는지 확인한다. 패시브 분석은 대상 요청 0건을 확인한다.
4. 격리된 평가 앱에서 상태 변경·근거 저장·민감값 제거와 정상/차단/실패를 확인한다. 이 문서에서 그 시험을 실행·통과한 것은 아니다.
5. 도구 결과를 관찰/신호로 정규화하고 독립 Judge의 근거 기준을 통과한 결과만 확정한다.
6. LLM 미설정·오류·시간 초과·출력 거절에서도 프로그램이 기본 도구를 호출하고 근거 판정·보고를 마치는지 확인한다. AI 작업이 기본 작업의 예약 예산을 소진하지 못하게 한다.
7. 작업별 미노출 도구·위조된 목록·반복 호출·과도한 결과를 주입해 호출 거절과 상한·요약 한계 표시를 확인한다. 모델별 전체/부분 노출은 실행 권한·정책·도구 구현을 고정한 대역에서 비교하고 실제 진단 성능과 함께 평가한다.
8. 미등록/만료/취소 대상과 위조 허가 참조·리다이렉트로 범위를 넓힐 수 없는지 확인한다. 기본/AI 작업과 내부/파생 요청의 정책·전송·근거 감사 연결 및 기록 유실/전송 여부 불명 표시를 검증한다.
9. 미발견·관찰 부족·KG/문맥 누락·추론 누락·정책/실행/판정 제한을 분리할 결과를 남긴다. 고정 입력 추론 평가는 실대상 추가 탐색 없이 수행하고 E2E에서는 전체 미탐과 최초 미충족 단계를 함께 보고한다.

관찰 어댑터·SDK·저장/로그 경계가 바뀌면 과거 검증을 이월하지 않고 비밀 canary·동시 계정/응답 귀속·잘림/누락·시계 역행/재시작을 다시 검증한다. 경과시간과 감사 벽시각·절대 만료는 구분하며 상세 품질 계약은 [아키텍처 8.4절](mcp-architecture.md)을 따른다.
